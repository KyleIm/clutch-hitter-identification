# Repository instructions

- Build a reproducible data science portfolio project using baseball as the application. Follow the requested analysis step and keep its scope focused.
- Inspect the README, scripts, dependencies, schemas, figures, derivations, Git status, and recent commits before editing.
- Preserve the hierarchy and existing RISP and LIPS entry points. Reuse datasets and functions. Preserve existing outputs unless an update is required.
- Keep reusable analysis code in `Script/` and source data in `Data/`.
- Generate results with reproducible scripts. Record assumptions and changes in methodology and update requirements.txt for new dependencies.
- Run the relevant tests and reproducibility checks before claiming completion.
- Commit or push only with explicit authorization.

## Documentation

- Keep the root README concise. Update its findings and navigation after each analysis step.
- Store mathematical derivations under `docs/methodology/` and completed reports under `docs/analysis/`. Number reports sequentially.
- Store generated tables and figures in the corresponding `Results/` subdirectory.
- Update the corresponding report whenever an analysis changes. Update `docs/roadmap.md` at each step and remove completed tasks.
- Use consistent terminology and file naming. Verify Markdown links and figure references after moving or renaming files.
